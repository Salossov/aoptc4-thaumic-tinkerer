# Thaumic Tinkerer

<img src="src/main/resources/logo.png" alt="Thaumic Tinkerer" width="128" height="128">

Неофициальный порт **Thaumic Tinkerer 2.5-1.7.10-164** на **Minecraft 1.21.1 / NeoForge**, использующий публичный API AOP: Thaumcraft 4.

[English](README.md) | [Авторство и лицензия](NOTICE.md)

## О проекте

Аддон включает устройства, набалдашники, зачарования, насыщенные посевы и огонь, управление големами и периферию ComputerCraft. Содержимое KAMI включает материалы, снаряжение, пробуждённые инструменты, крылья, сумку, строительное зеркало, врата, Recall, Shadowbeam и бедроковое измерение.

Предусмотрены необязательные интеграции с CC: Tweaked, Applied Energistics 2, Botania, EnderStorage, CB Multipart и неофициальным портом Blood Magic. Tinkers' Construct, IndustrialCraft 2 и OpenComputers не включены. Устаревшая интеграция VersionChecker удалена; замена механизма обновлений запланирована.

Ручная проверка игровых, графических и многопользовательских сценариев продолжается.

## Требования и установка

| Компонент | Требование |
| --- | --- |
| Minecraft | 1.21.1 |
| Java | 21 |
| NeoForge | От 21.1.252 в пределах ветки 21.1 |
| AOP: Thaumcraft 4 | Совместимая сборка 1.0.0 |
| AOP: UI | Совместимая сборка 0.7.x |
| Curios | От 9.5.1+1.21.1 в пределах ветки 9.x |

Игровой файл `ThaumicTinkerer-1.21.1-1.0.0.jar` и обязательные зависимости устанавливаются на клиент и сервер. Все зависимости должны быть предназначены для Minecraft 1.21.1 / NeoForge. Отдельный API JAR Thaumcraft используется только при разработке и не устанавливается как мод.

Сборки ядра и аддона должны быть совместимы. Аддон использует публичные контракты, добавленные при переносе, поэтому более старый артефакт ядра с тем же номером версии может не подходить. Оба компонента следует обновлять вместе.

Для необязательных интеграций устанавливаются их собственные зависимости. **AOP:TC4 Compact** отдельно предоставляет рецепты JEI/EMI и подсказки Jade/WTHIT для устройств Tinkerer. Сам Tinkerer не требует просмотрщиков рецептов и подсказок.

## Настройка

Меню AOP: UI открывается через Mods, шестерёнку Таумономикона или меню паузы. Клиентские изменения сохраняются сразу. Серверные изменения сохраняются кнопкой **«Сохранить»** или клавишей **Esc**. В многопользовательской игре требуется OP 4; владелец одиночного мира может менять настройки без читов.

Параметры с меткой перезапуска применяются после перезапуска. Исходные файлы конфигурации, ключи и значения по умолчанию сохранены. Дочерние настройки сохраняют индивидуальные значения при отключении родительского параметра.

## Сборка из исходников

Требуются JDK 21 и совместимые артефакты AOP: UI, API и игрового ядра Thaumcraft. API и ядро собираются в репозитории ядра задачами `:api:assemble :mod:assemble` с указанием `aopUiJar`.

Из этого репозитория выполняются команды:

```powershell
$dependencies = @(
    '-PaopUiJar=C:/dependencies/aopui-1.21.1-0.7.0.jar'
    '-PthaumcraftApiJar=C:/dependencies/thaumcraft-api-1.0.0.jar'
    '-PthaumcraftRuntimeJar=C:/dependencies/thaumcraft-1.21.1-1.0.0.jar'
)
./gradlew.ps1 build @dependencies
```

В Linux и macOS используется `sh ./gradlew` с теми же параметрами Gradle. JAR также можно разместить в `libs/` с именами, указанными в `build.gradle`.

Необязательные API загружаются из Maven-репозиториев авторов. Для разработки предусмотрены параметры `botaniaJar`, `enderStorageJar`, `codeChickenLibJar` и `multipartJar`.

Игровой артефакт: `build/libs/ThaumicTinkerer-1.21.1-1.0.0.jar`. Проверочный код и классы сторонних модов в него не включаются.

## Проверки

`build` компилирует проверочные исходники и выполняет отдельные проверки данных и отображения. Нативные GameTest запускаются отдельно и требуют игрового ядра через `thaumcraftRuntimeJar`.

Интеграционные профили включаются параметрами `withComputerCraft`, `withAppliedEnergistics`, `withBotania`, `withEnderStorage` и `withMultipart` со значением `true`. Профиль Blood Magic дополнительно требует явно указанных JAR Blood Magic и Modopedia.

Сообщение об ошибке должно содержать версии компонентов, шаги воспроизведения и соответствующий журнал. Успешная компиляция не подтверждает полную совместимость игровых, графических и многопользовательских сценариев.

## Непрерывная интеграция

Для выпуска обычного GitHub Release откройте **Actions → Build and release → Run workflow** и включите **release**. Релиз получает тег `v<версия>`. Пустое поле **version** использует `mod_version` из `gradle.properties`; значение `major.minor.patch` переопределяет версию только для этого запуска. Выбранная версия применяется к метаданным JAR, именам файлов и тегу; исходные файлы workflow не изменяет. Суффиксы предварительных версий в режиме релиза отклоняются. Существующие теги релизов не перезаписываются. При выключенном **release** ручной запуск только собирает артефакты. Локальный `act` ничего не публикует. Заметки обычного релиза содержат все коммиты после ближайшего предыдущего обычного релиза в выбранной истории, ссылки на коммиты и сравнение. Первый релиз включает всю историю. В nightly этот список не добавляется.

Для локального запуска `act` подготовьте совместимые исходники зависимостей в `.dependencies/aopui`, `.dependencies/thaumcraft`, затем выполните `act workflow_dispatch --input release=true`. Локальная проверка использует эти каталоги и пропускает публикацию на GitHub. Для приватных зависимостей задайте необязательный секрет `DEPENDENCY_TOKEN` с правом чтения соответствующих репозиториев.

GitHub workflow запускается при изменениях кода и сборочных файлов. Правки только документации сборку не запускают.

| Переменная репозитория | Назначение / значение по умолчанию |
| --- | --- |
| `THAUMCRAFT_REPOSITORY` | Исходники ядра; `Salossov/aop-thaumcraft-4` |
| `THAUMCRAFT_REF` | Ревизия ядра; `main` |
| `AOPUI_REPOSITORY` | Исходники AOP: UI; `Salossov/aop-ui` |
| `AOPUI_REF` | Ревизия AOP: UI; `main` |

Для сборки используются совместимые ревизии ядра и аддона. Загрузка приватных зависимостей требует токен с правом чтения репозитория.
